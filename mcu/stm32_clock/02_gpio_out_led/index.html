    引脚输出控制 LED

    怎么点亮LED¶

    我们在谈 GPIO 输出的时候，一般就是说让这个引脚输出高电平或者低电平，高电平和低电平是指单片机的逻辑电平，比如STM32的逻辑电平，高电平就是 +3.3V，低电平就是 0V。

    而我们，如果要使得一个接在单片机上的LED灯点亮，是不是就得看，应该让单片机输出逻辑高还是逻辑低来使得 LED 灯点亮，这时候就得看实际的电路，比如我们的 开发板上面的 LED 就是阳极接了高电平，阴极接了单片机引脚，那么单片机引脚输出低电平就能点亮LED。

    所以，怎么点亮LED。在LED阴极接到单片机引脚的情况下，单片机对应引脚输出低电平就能有电流流通（就能点亮），高电平就没有电流流通（就会熄灭）。

    怎么让单片机输出高低电平¶

    我们会发现单片机引脚有很多的模式。这个我们可以通过代码 Library/stm32f10x_gpio.h 中的下面代码得知。有8种模式，其中我们这部分只管输出。也就只讨论 GPIO_Mode_Out_OD 和 GPIO_Mode_Out_PP，其他情况暂时不考虑。

    所以 OD 和 PP 分别是什么意思呢，OD 是开漏输出，PP是推挽输出，这两种输出有什么不一样呢。

    可以看我这篇博客 你怎么理解单片机开漏输出和推挽输出？。

    我们这里，选择使用 PP 模式，也就是推挽输出模式，因为我们没有外部电压提供高电平。

    我们现在需要配置 GPIO ，我们把这个文件写在 STM32F10x/bsp_gpio 中。为什么不直接写 LED，因为想的是做一套自己的接口，这样更方便移植，以后就只需要改变 bsp_gpio 中的内容，而不用改变 LED.c中的内容。

    #include "bsp_gpio.h"

static GPIO_TypeDef *const s_gpioBases[] = {GPIOA, GPIOB, GPIOC, GPIOD, GPIOE};

void gpio_drv_init(void)
{
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC,ENABLE);
    {
        GPIO_InitTypeDef GPIO_InitStruct;

        GPIO_InitStruct.GPIO_Pin  = GPIO_Pin_13;
        GPIO_InitStruct.GPIO_Mode = GPIO_Mode_Out_PP;
        GPIO_InitStruct.GPIO_Speed= GPIO_Speed_50MHz;

        GPIO_Init(GPIOC,&GPIO_InitStruct);
    }
}

void gpio_drv_write(gpio_port_t port, uint16_t pin, gpio_level_t level)
{
    uint16_t gpio_pin = 1 << pin; // 将引脚号转换为对应的 GPIO_Pin_x 值
    GPIO_TypeDef *gpio_base = s_gpioBases[port];

    if(level == GPIO_HIGH)
    {
        GPIO_SetBits(gpio_base,gpio_pin);
    }
    else
    {
        GPIO_ResetBits(gpio_base,gpio_pin);
    }
}

    我们使用不同的单片机，肯定会有不同的引脚驱动方式，但是底层逻辑无非就是初始化，然后调用功能，那我们就可以将这个内容抽象出来，将这个GPIO的初始化以及读写接口，变成一个通用的接口。

    这样不管你是使用标准库，还是 HAL库，还是寄存器，或者其他的什么单片机，我们都可以使用这个接口，每次就只需要改接口中的配置，而不需要改上层的 led 中的内容。

    因为所有接口自定义，使得在自己多个项目中的可移植性会变强。

    我们这里实现的 gpio_drv_write 就是把对应的引脚电平拉高拉低。

    #ifndef _BSP_GPIO_H
#define _BSP_GPIO_H

#include "stm32f10x.h"

typedef enum
{
    kGPIOA = 0,
    kGPIOB,
    kGPIOC,
    kGPIOD,
    kGPIOE,
} gpio_port_t;

typedef enum
{
    GPIO_LOW = 0,
    GPIO_HIGH
}gpio_level_t;

void gpio_drv_init(void);
void gpio_drv_write(gpio_port_t port, uint16_t pin, gpio_level_t level);

#endif /* _BSP_GPIO_H */

    #include "led.h"
#include "board.h"

void led_on(void)
{
    gpio_drv_write(LED_PORT, LED_PIN, LED_ON_LEVEL);
}

void led_off(void)
{
    gpio_drv_write(LED_PORT, LED_PIN, LED_OFF_LEVEL);
}

    总结¶

    这套处理方式在跨平台的时候会比较有用，而且现在只是 gpio 和 led 的代码比较少，所以体现不是很明显，觉得这样弄反而浪费了，但是如果加上 IIC OLED 这些后，这个驱动层次会更清晰。我觉得，这是一个比较好的分割方案。
